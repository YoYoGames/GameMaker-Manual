Making UI

On the Drawing page, we talked about drawing things within objects that are displayed in the room. Now, let's look at drawing things on the screen, to display GUI information, HUD etc. to the player. For this we make use of UI Layers.

UI Layers display their contents on the GUI Layer, which is a special drawing layer of a fixed width and height that is drawn over the contents of the room. The great thing about the GUI layer is that it doesn't move with the room's camera, so it's the ideal place to add static GUI (or HUD) items, like scores, healthbars and other information that your game requires to communicate to the user. You can find out more information on the GUI layer from the Draw Events section of the manual.

 Rooms can be larger than the screen size, so you can have large levels for the player to move around in. This means that in the Room Editor (or in code) you need to define a camera that follows the action of your game.

This is basically a way of setting up a fixed area of the screen to display different parts of the larger room based on - for example - the player position in the room, and is used in a lot of games. Think of the way that the view always follows the main character in classic games like Mario or Zelda. That's done with cameras. For information on setting up cameras, see Cameras And Viewports.

Drawing on GUI

All the drawing techniques covered on the Drawing page can be used on GUI, simply by creating an object and placing it in a UI layer in a room:

Anything you draw in the Draw event of that object will appear on the GUI layer, which you can see if you have a camera in the room while drawing something on GUI.

At runtime you will see the instance sticks to the screen, and not moving as the camera pans:

You can extend this to text, healthbars, or anything that can be rendered by an object. Everything will appear on the UI layer that it is placed on.

However, UI layers also come equipped with their own features, and you can place text and images natively in the Room Editor.

Placing Elements In UI Layers

Text can be placed directly in a UI layer by dragging a font asset into the canvas, and images can also be placed by dragging sprite assets in. They are always placed inside Flex Panels:

These elements appear at runtime as they were in the editor. You can modify such text at runtime using the Text Element functions:

// Get element
var _text_element = layer_text_get_id("UILayer_1", "text_33B7665A"); // Use the default element ID or a custom one

// Modify element
layer_text_text(_text_element, "Start Recipe");

Mouse Input

Objects use GUI mouse coordinates when placed on a UI layer. This means all Mouse events and the coordinates returned by mouse_x/mouse_y are on the GUI layer.

For example, you can use the Mouse Enter and Mouse Leave events to change the opacity of a button object and the Mouse Left Pressed event to run some code:

Mouse Enter

image_alpha = 0.7;

Mouse Leave

image_alpha = 1;

Left Pressed

var _text_element = layer_text_get_id("UILayer_1", "text_33B7665A");
layer_text_text(_text_element, "Button (Clicked)");

Designing Layouts

By now you know how to place objects, images and text in UI layers, and how to interact with them. The next step is to design a layout, using the example of a HUD screen used to display player information.

 For this example, we will use the User Interfaces prefab collection which can be downloaded from the Prefab Library.

Setting the Canvas Size

UI layers always adapt to the size of the game window.

The editor uses the size of the room as the preview canvas for UI layers, so everything you place in UI layers stretches to the entire size of the room.

This is inconvenient if your room is too large. While designing UI, use the "UI canvas preview" feature to set a size for your UI preview canvas:

Here, the editor is using a 1280x720 canvas to preview UI. At runtime, this stretches to the game window.

You can use this menu to preview your UI at different sizes and orientations, for example to see how the UI would look on mobile.

Left Panel

In this example, we will create a HUD that has progress bars on the left of the screen, and text on the right.

In a UI layer, add a new Flex Panel through the right-click menu.

Set its name to "Left" (using F2 or the RMB menu), as this will our panel containing our UI elements on the left side of the screen.

Set its width and height to auto and position to "Absolute".

This does two things:

  • With the size set to auto, the panel resizes itself to fit its contents (i.e. the progress bars we place inside it)
  • With the position set to "Absolute", you can move this panel anywhere on your screen with your mouse

 Using absolute panels is an easier, more WYSIWYG approach to designing UI in GameMaker. To create more complicated and expandable interfaces, it is recommended to play with the Flex Properties of the parent flex panel to control how panels inside it are laid out. See UI Element Properties for information on those options.

From the User Interfaces prefab collection, drag and drop the ProgressBar object into your Left panel.

This will create a new flex panel under Left, with the ProgressBar instance inside it. With that new flex panel selected, hit CTRL/CMD+D twice to create two copies:

In the UI layer list on the left, select your Left panel. In the Inspector, scroll to the bottom and set the vertical gap to 10:

With the Left panel selected, in the canvas, drag it to the bottom-left corner of the screen.

It should now remain there, and you can add/remove panels as you need.

Right Panel

For the text on the right side of the screen, create a new Flex Panel under the layer root and rename it "Right".

Similar to the Left panel, set its width/height to auto and position to "Absolute".

Create a Font Asset and set it to the font and size you want. Drag and drop it into the Right panel, using CTRL+D again to duplicate it. Select each text element and edit its text in the Inspector.

After duplication, add a vertical gap to the Right panel as well, and then drag the panel to the bottom-right corner of the screen:

You probably want to align the text to the right edge of the panel. For this, set the Align Items property of the Right panel to "Flex End":

For information on this property and other similar properties, see UI Element Properties.

Editing At Runtime

To modify the text, simply edit their element names by double-clicking on them in the canvas or the UI layer list.

Change the default "text_XXXXXX" identifier to something you can identify easily, and use the code shown above under the "Placing Elements in UI Layers" section to modify the text at runtime.

To modify the progress bars, also edit their identifiers, for example I will use "bar_health" for one ProgressBar instance:

In your code, modify its current_value variable to a value between 0 and 100:

bar_health.current_value = 20;
